Distributed Compute Engine

A small C++20 cluster that splits jobs between workers and retries unfinished work when a worker disconnects.

How it works

CLI / browser ── HTTP :8080 ── Coordinator
                                │
                     FIFO queue + worker registry
                                │
                  Length-prefixed JSON / TCP :9000
                     ┌──────────┼──────────┐
                  Worker 1   Worker 2   Worker 3
                   bounded computation pools

Boost.Asio keeps networking separate from computational work. Workers send heartbeats every 500 ms. The scheduler reserves capacity before dispatch, chooses the lowest outstanding-work-to-capacity ratio, and requeues unfinished tasks when a session fails.

Each assignment gets a fresh attempt ID. Only the current live session and attempt can publish a result: at-least-once execution with idempotent result acceptance.

What the benchmarks showed

There are two workloads: counting primes and calculating statistics over a numeric CSV. Each job is split into tasks. The coordinator merges their results into one answer.

Run it

git clone https://github.com/Sourya-Prabaharan/dce.git
cd dce
sh scripts/deps.sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
ctest --test-dir build --output-on-failure
build/dce-cli generate --output data/numbers.csv --rows 10000
sh scripts/local.sh

Open http://127.0.0.1:8080 for the actual worker health, submission forms, job progress, and results. In another terminal:

build/dce-cli demo --end 2000000 --partitions 12
build/dce-cli demo --type csv --file numbers.csv
sh scripts/failure-demo.sh

Docker Compose also launches a coordinator and three workers. Containers on one computer are logical worker nodes. Docker can restart processes; DCE detects lost sessions and reassigns tasks.

What’s missing

The implementation uses C++20, Boost.Asio, nlohmann/json, and CMake. It accepts two built-in workloads. The local dashboard can submit jobs and show workers as they run.

Jobs live in coordinator memory. There is no coordinator failover, durable state, authentication, or TLS. Run on a trusted private network. Shared CSV inputs must remain identical and immutable. Persistence and better scheduling fairness would be useful next steps.
